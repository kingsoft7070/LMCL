# 开发记录

## 先做什么

先跑通普通使用流程：下载游戏、安装或导入整合包、管理实例、启动单人或多人游戏。普通功能不依赖服务器接口，也不要求加入任何社区。当前已提供 Electron 临时界面，正式 UI 后续按设计稿接入。

Windows 预览版已接入标准原版下载、离线角色、Java 选择与游戏启动；实际整合包导入、加载器和自动更新执行器仍未接入。详细范围见 [预览版说明](preview.md)。

服务器优化作为可选模块，再接上状态查询、按服安装和整合包同步。LID 是一个接入方，其他服务器使用相同接口。公开版本不打包 LID 内容，也不自动发现或连接 LID。

下载功能覆盖游戏版本、加载器、模组和整合包。加载器先接 Fabric，再逐步补 Forge、NeoForge 和 Quilt。下载目录和安装流程参考成熟启动器的使用习惯，代码独立实现。

邀请码保留为可配置的权限机制。服务商可以限制自己的整合包或内测内容；第三方服务器权限不影响普通模式使用本地整合包。LMCL 自身是否还有独立内测范围尚未确定。

## 模式与发行内容

默认普通模式，无预设服务器。服务器模式允许用户添加一个或多个服务商接口，模式切换只改变入口与服务器目录查询，不替换账户、实例或下载任务。已经安装的整合包仍是本地实例，离开服务器模式也能找到；具体能否离线运行由整合包自身决定。

只有用户明确点击“进入服务器”才附加联机目标；普通启动不因为实例曾来自服务器就自动进服。服务商离线时显示状态未知，普通功能仍可使用。

服务商目录、服务器 ID 和包 ID 按服务商隔离。公开仓库只放通用代码、接口说明与虚构示例；LID 地址、品牌素材、包内容和凭据单独维护。[接口草案](server-api.md)

## 账户

支持微软正版、LittleSkin 和离线三种方式，按这个顺序推荐。登录失败时不能自动切换成离线账户，同名的不同账户也不能自动合并。

LittleSkin 需要处理角色选择、会话刷新和 authlib-injector。网页授权优先考虑 OAuth，设备码登录需要给 LMCL 注册应用并申请白名单。账户令牌放系统凭据存储，密码不落盘。

服务器接受哪种账户由服务器决定，启动器不修改服务器的验证方式。

## 整合包更新

普通整合包与服务器整合包使用同一个实例和更新核心。前者可以来自本地导入或通用下载源，无需服务器资料。服务器接入信息只是附加的来源信息和联机目标。

服务器发布者关联经过测试的客户端包。服务端的 mods 目录不能直接复制给玩家；服务端改动后，需要先生成并测试新的客户端版本，再发布。

每个服务器使用独立实例。包管理的文件和玩家数据分开，存档、截图、个人设置不能被更新覆盖。只下载新增、变更或缺失的文件，校验完成后再切换版本。游戏还在运行时延后应用。

当前计划器只计算差异，不读写游戏文件。自装模组、受管文件被手动修改、路径冲突等情况会返回冲突，留给后续交互处理。

正式执行器还需要清单签名验证、下载校验、目录锁、暂存、提交和中断恢复。执行前必须重新检查磁盘状态，不能只凭计划结果直接写文件。

## 基岩版

只在 Windows 工具箱中提供打开已安装基岩版的入口，使用系统的 `minecraft://` 协议，不负责安装或更新。尚未做 Windows 真机验证。

## 验证

自动测试覆盖账户顺序、离线 UUID、更新差异、配置保留、运行中延后更新、Windows 路径和符号链接冲突，以及模式切换、空服务器配置和服务商隔离。

规则测试不代表真实账户授权或 Minecraft 图形运行测试。Windows 构建还会执行桌面冒烟测试和打包后 EXE 冒烟测试，验证界面、头像、IPC、账户保存与模式切换；游戏图形运行仍需真机人工验证。
